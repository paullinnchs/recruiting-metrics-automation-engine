# Delivery Process

Internal/operational. Companion to `02_INTERNAL_SOP/Operator_SOP.md` — this document focuses specifically on the delivery stage.

## Process

```
Intake received -> Validate -> Process -> QA -> Deliver
```

1. **Intake received** — client files arrive, get placed into `client_intake/<client_id>/` per `Operator_SOP.md`.
2. **Validate** — handled automatically by `app/main.py` on execution; review the console output.
3. **Process** — `python app/main.py client_intake/<client_id>` runs the full analysis and generates the report.
4. **QA** — work through `02_INTERNAL_SOP/QA_Checklist.md` in full before moving to delivery. No exceptions for repeat clients.
5. **Deliver** — send the client the two client-facing files only.

## Primary Client Deliverables

- `Consolidated_Client_Report_<client_id>_<date>.docx`
- `Consolidated_Client_Report_<client_id>_<date>.pdf`

These two files are the entire client-facing deliverable. Nothing else generated by the pipeline should be sent to a client.

## What Is NOT a Client Deliverable

- `consolidated_report_<client_id>_<date>.json` — internal data, not formatted for client review
- `consolidated_working_copy_<client_id>_<date>.md` — internal working copy
- Individual Tier 1 / Tier 2 / revenue-leak JSON outputs — internal traceability/debugging only

If a client specifically asks for underlying data, that's a case-by-case business decision, not something to send by default.

## Simple Delivery Folder Convention

If keeping a local record of what was sent, a simple convention:

```
deliveries/<client_id>/<date>/
    Consolidated_Client_Report_<client_id>_<date>.docx
    Consolidated_Client_Report_<client_id>_<date>.pdf
```

This is a suggested convention, not a required part of the engine — the engine itself always writes to `outputs/reports/`.
